# 我不打你，我打你的供應商｜立體版

`redteam-3d.html`：單一檔案，雙擊即可開啟，沒有其他資產。三條路線、九個關卡、八項措施沿用 `redteam-supply-chain.html`（平面版），兩者互不相依；情境仍是虛構的。

## 0. 這次精修（依自我檢視）

| 問題 | 修改 |
|---|---|
| 每季只能推動三項的額度卡手，也看不出用意 | 取消額度。措施可以自由接上與收回；重新確認不再消耗任何東西。 |
| 「進入下一季」同時負責重置額度與觸發變動，意義混在一起 | 改成「時間快轉一季」，只做一件事：讓供應商那邊發生變動，看哪些鎖上的關卡還算數。 |
| 按措施之前，不知道它會影響哪裡 | 每項措施多一行「作用於：哪條路線的第幾步、是要求還是確認」；動力盤會標出與目前這一關有關的措施。 |
| 導覽要使用者去右側找指定的那一項 | 該按的按鈕直接放在對話框裡，動力盤同步提示。 |
| 路線被擋下後，對話停在「這一步我走不到」，看不到被擋的那句話 | 自動回到被擋的那一步，紅隊會說出他為什麼過不去。 |
| 走完一條路線後沒有下一步 | 多了「看下一條路線」；三條都看過後引導到總結。 |
| 損害只出現在文字清單 | 目標方塊被打到時轉紅，並標示後果：被讀走、被植入、停擺；路線被擋下就恢復。 |
| 場景同時顯示三條路線的徽章，互相遮擋 | 只顯示目前路線的徽章；其他路線保留虛線與牆。 |
| 對話框太高，把場景擠小 | 併行、縮短按鈕文字，1366 寬時高度由約 300px 降到約 215px。 |
| 「回到題目」按鈕看不出是什麼 | 改名為「總結」，內容不變。 |

## 1. 這一版改了什麼

### 進場的理解時間

平面版一打開就有十二張卡片、十六格射程表、八項措施與額度。這一版把它們拆成前一分鐘的導覽，一次只出現一件事：

| 階段 | 畫面上有什麼 | 使用者做什麼 |
|---|---|---|
| 開場 | 四座平台、一句情境、紅隊的一句話、一顆按鈕 | 按「看紅隊怎麼走」 |
| 看紅隊 | 路線一的紅色光路，一次一步 | 按三次「紅隊的下一步」，看到損害 |
| 接上契約 | 對話框出現一顆按鈕；動力盤出現並提示同一項 | 按一下：光軌伸到供應商 A，關卡變成紙牆，紅隊說「我賭它沒開」 |
| 接上內部監督 | 對話框換成下一顆按鈕 | 按一下：牆立起來，紅隊被擋，損害劃掉，目標方塊由紅轉藍 |
| 規則小結 | 一句話：有人提出要求，也有人確認做到，關卡才算鎖上 | 按「開始自由探索」 |

之後才開放其餘兩條路線、六項措施、「時間快轉一季」與「總結」。導覽隨時可跳過；講者重複示範時按「跳過導覽，直接探索」即可。

畫面上的文字也減少了：場景裡只留編號與鎖的圖示，說明集中在底部的對話框，一次只講一步。

### 立體場景

| 畫面元素 | 代表什麼 |
|---|---|
| 四座平台，由左到右 | 上游元件、業者 B、供應商 A、本公司；越左離控制越遠，越暗 |
| 發亮的藍色方塊 | 目標：客戶資料、線上服務。目前路線走得到且仍有損害時轉紅，並標示後果 |
| 紅色流動光路 | 紅隊的路線，流動方向就是攻擊方向 |
| 立起來的牆 | 關卡。只有地上的虛線框是沒有關卡；斜紋虛線牆是紙上關卡；實心發光牆是已鎖上；琥珀色虛線牆是需重新確認 |
| 平台前緣的藍色光軌 | 契約的射程：接上條款才會亮到供應商 A，有轉委託條款才亮到業者 B，上游永遠是斷的 |
| 斜紋短軌 | 認證涵蓋的範圍（只有一部分） |
| 本公司上方的光幕 | 法令：只壓在本公司 |
| 本公司平台的外框光 | 內部政策：有自己人去查 |
| 紅色菱形 | 紅隊目前走到哪裡；被擋下時停在牆前 |

操作：拖曳場景空白處可旋轉視角；「視角」按鈕在立體、另一側、俯視之間切換（俯視等於平面版的板子）；「亮色」切換成白底，適合燈光較亮的教室投影。

## 2. 技術說明

用 CSS 3D（`perspective` 與 `transform-style: preserve-3d`）做，不是 WebGL。

- 選它的原因：不需要任何外部套件，檔案只有 60 KB 左右，離線雙擊可用；場景裡的編號、路線標籤都是真正的按鈕，鍵盤與螢幕報讀都碰得到；文字不會因為貼圖而模糊。
- 代價：沒有真正的光源與陰影，發光效果是用外暈模擬的；視角旋轉限制在一個範圍內（俯仰 0～72 度、左右各 55 度）。
- 若需要自由環繞、光影或粒子等效果，要改用 Three.js，並把函式庫內嵌進檔案（約多 600 KB 以上）。目前的內容沒有非它不可的地方。

動態只有四種，都對應資訊：平台依序落下（介紹四層）、光路流動（攻擊方向）、牆升起（關卡狀態改變）、新揭露的步驟淡入。勾選「減少動態」或系統設定偏好減少動態時全部停用，畫面資訊不變。

## 3. 使用方式

- 滑鼠或觸控：按對話框裡的按鈕前進；點場景裡的編號徽章可直接跳到那一步；右側動力盤接上或收回措施。
- 鍵盤：Tab 依序進入工具列、路線選單、場景、對話框、動力盤；Enter 或 Space 執行；Esc 關閉「總結」或取消重置。
- 「文字版」把三條路線、九個關卡、八項措施與紀錄以表格列出。
- 沒有計時、沒有分數；「上一步」與「重置」隨時可用，重置需按兩次。

### 規則

- 關卡有四種狀態：沒有關卡（沒有任何要求到得了）、紙上關卡（有要求沒人確認）、已鎖上（要求加確認）、需重新確認（確認過但環境變了）。
- 措施沒有數量限制，隨時可以接上或收回。每一項的代價寫在滑鼠提示與文字版裡，接上時也會顯示。
- 「時間快轉一季」：第 2 季業者 B 調整架構，第 3 季供應商 A 的維運加入外包人力，之後沒有新的變動通知。受影響且已鎖上的關卡會變成需重新確認。
- 需重新確認的關卡可以手動重查；確認來自「每季覆核」或「演練」的，再過一季會自動補上；只靠認證報告確認的不會，因為那份報告講的是變動前的狀況。

三條路線、九個關卡與八項措施的對照表見 `README-redteam.md` 第 3.3 節。該文件第 3.4 節的「一季只能推動 3 項」在這一版已經取消。

## 4. 執行環境

1. **本機伺服器。** 在檔案所在資料夾執行 `python3 -m http.server 8000`，開啟 `http://localhost:8000/redteam-3d.html`。頁面只請求這一個檔案。
2. **直接雙擊。** 支援。
3. **第三方資產。** 沒有。不載入 CDN、套件、網路字型或圖片；使用系統內建的繁體中文字型。
4. **實測過的瀏覽器。** 只有 Chrome for Testing 153（Linux，無頭模式，軟體繪圖）。Edge、Firefox、Safari 沒有實測。

## 5. 測試結果

無頭 Chrome 自動化操作，56 項檢查全數通過。

| 驗收項目 | 做法 | 結果 |
|---|---|---|
| 導覽 | 開場畫面的元件數；逐階段前進；導覽中點其他措施；導覽中按「上一步」；跳過 | 開場只有兩顆按鈕，動力盤、路線選單、場景按鈕都未出現；各階段行為正確 |
| 規則 | 八項措施一次全部接上再全部收回；畫面上不再出現額度字樣；被擋下時對話回到被擋的那一步；每項措施都有「作用於」；快轉兩季與重新確認 | 通過 |
| 流程銜接 | 走完一條 → 看下一條 → 三條看完 → 總結；場景只顯示目前路線的徽章 | 通過 |
| 不同探索順序 | 40 組隨機順序，各 45 步，混合措施、時間快轉、步驟、路線、視角、重新確認 | 紀錄始終連續；都能把九個關卡鎖上，最終結果相同 |
| 返回、修改、重置 | 連續「上一步」回到起點；重置需按兩次，Esc 可取消 | 通過 |
| 連點與快速切換 | 同一措施連點 101 次；文字版、視角、主題、季度、選取共 300 次；重置連點 40 次 | 狀態一致 |
| 鍵盤 | 只用鍵盤走完導覽、揭露步驟、接上措施、時間快轉、切視角、開關「總結」、文字版、上一步、重置 | 通過；焦點在重繪後保留，導覽中會落在該按的按鈕上 |
| 降低動態 | 系統偏好與頁面核取方塊 | 動畫全部停用，關卡與路線完整顯示 |
| 尺寸與視角 | 1920×1080、1440×900、1366×768、1280×720，各測立體與俯視；另測拖曳旋轉與亮色 | 場景中的按鈕與標籤都沒有被對話框或動力盤遮住；無水平捲動 |
| 斷網 | 離線以 `file://` 開啟 | 可運作，只有 HTML 本身一個請求 |
| 觸控 | 模擬點按 | 可走導覽、跳過、接上措施 |

場景會依視窗自動縮放。目前步驟的徽章實際高度：1920 寬約 39px、1440 寬約 38px、1366 寬約 30px、1280 寬約 23px。

## 6. 已知限制

- 瀏覽器只測過 Chrome，而且是無頭的軟體繪圖。CSS 3D 的前後遮蔽在不同瀏覽器之間差異比一般版面大，Safari 尤其需要實機確認。課前請用現場的電腦與投影機開一次；若立體視角顯示異常，切到「俯視」可以照常使用。
- 暗色畫面在燈光明亮的教室裡對比會下降，請改用「亮色」。
- 1366×768 以下的筆電，場景會縮得比較小（約為 1920 寬時的三分之二）。投影建議 1920×1080，或用瀏覽器全螢幕。
- 平台上的名稱是貼在平面上的字，旋轉到極端角度時不好讀；按一下「視角」可回到預設。
- 沒有用螢幕報讀軟體實測；觸控只做過模擬點按，沒有在實體平板上試過拖曳旋轉。
- 「前一分鐘學會規則」是依點擊次數設計的，沒有找真人試用過。
- 取消額度之後，把八項全部接上就能鎖住九個關卡。先後順序的取捨不再由機制強迫，要靠講者提問，或用「時間快轉」帶出鎖上的關卡會失效。
- 模型的簡化與內容限制與平面版相同：關卡只看「有沒有要求」與「有沒有確認」；認證核對結果是寫死的；法令沒有條號與案例；變動只有兩則。
- HTML 末端留有唯讀的 `window.__app` 檢查點供自動化測試使用，不影響操作。
